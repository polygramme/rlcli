rlcli is a Python CLI that runs fused RL losses like **GSPO** on your own GPUs in a single `forward_backward` call, backed by SkyRL. Hosted Tinker does not serve GSPO natively: reproducing it there costs a 2-pass round-trip (fetch logprobs, compute the loss client-side, ship the reweighted batch back). rlcli gives you the fused 1-pass path locally, and [our benchmark](/concepts/benchmarks) measures a **23% step-time reduction and 29.8% throughput gain** on Qwen3-4B-Instruct-2507.

It is also the missing front door for the whole stack: the official `tinker` CLI has no `train` verb, and SkyRL has no CLI. rlcli wires them together so you can serve a model, run SFT or RL, and sample from checkpoints without leaving your terminal.

<Note>
  This package is `rlcli` on PyPI. Do not confuse it with `rl-cli` (Runloop's CLI), which is a different tool.
</Note>

## One-liners

```bash
# Start a local SkyRL server
rlcli serve start --base-model Qwen/Qwen3-4B-Instruct-2507 --backend fsdp --gpus 8

# Supervised fine-tuning
rlcli train sl --model Qwen/Qwen3-4B-Instruct-2507 --dataset conversations.jsonl

# RL with GSPO
rlcli train rl --model Qwen/Qwen3-4B-Instruct-2507 --loss gspo --dataset gsm8k

# Import chat dumps and pipe straight into training
rlcli import prod.jsonl -f openai | rlcli train sl --dataset - --model Qwen/Qwen3-4B-Instruct-2507
```
